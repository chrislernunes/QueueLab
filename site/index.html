queue_positioning

Deterministic replay and queue-position research for passive execution.

A passive order’s fill depends on queue priority the public feed does not contain. queue_positioning replays a price-level book, places hypothetical orders under explicit latency and queue assumptions, and records where those assumptions change the answer. It does not send orders and it is not a trading system.

01 — The research problem

Passive execution is a queue problem the tape does not solve.

A limit order that does not cross rests behind displayed size. Whether it fills depends on who cancels, who trades, and where it sat. Public Binance spot depth is market-by-price: each update is an absolute quantity at a price, not an order identity. A decrease can be a cancel, a trade the feed has not yet paired, or both. The slot of an order that was never sent is not in the file.

The quantities that matter for a passive decision — fill probability, implementation shortfall against the decision mid, and later adverse selection — are therefore estimates under a queue rule, not observations. Changing the rule, or the delay before the order arrives, can change the estimate. That sensitivity is the object of study.

What the public book can show

Displayed size at a price, best bid and ask, spread, mid, and prints with price, quantity, and a maker flag.

What it cannot show

Which resting order was cancelled. Hidden size. The queue slot of a hypothetical order. One-way latency. A historical L2 book from the public trade dumps — those dumps do not include diff depth.

02 — System architecture

One direction: events in, a book, then a counterfactual order.

Stages below are the modules that exist. Simulated orders never enter the public book. Python reads files the OCaml engine already wrote.

01Capture or fixture

scripts/capture_binance.py or generate-fixture. Capture is public streams, no API key, no orders.

02Normalize

binance_decoder turns REST snapshots and stream payloads into canonical events. Exchange timestamps are ms stored as µs.

03Validate

Manifest checksum, mixed-symbol checks, then a replay. An experiment refuses a dataset that fails.

04Depth sync + replay

Spot diff rules. Total order is exchange time, then kind, then seq_index.

05Queue + fills

Three models share join-at-back. Trades are the only fills. Ledger is integer average cost.

06Experiment

Latency grid or explicit intents. CSV and JSON under reports/. Figures are a later Python step.

07Checkpoint

Saved state is the depth-sync record, not the book alone. Suffix replay must match the full hash.

08Benchmark

Wall-clock of this binary, this machine. Not a portable throughput claim.

03 — How it works

Integrity first, then an explicit fiction about the queue.

Normalization and integrity

Canonical events are snapshot, depth, trade, aggregate trade, and gap. Prices and quantities are integers at the instrument scale. Extra fractional digits are an error. A dataset is a manifest.json plus events.jsonl. Validation recomputes the SHA-256 and fails on a mismatch, a gap, a broken sync, a negative quantity, or mixed symbols.

Book and replay

The book is a map from price to displayed quantity. Zero deletes. Replay orders by exchange time when it is non-zero, otherwise receive time. On a tie the order is snapshot, trade, aggregate trade, depth, gap, then source index. Trades sit before a same-timestamp depth update so a print is not also counted as a cancel. That is a documented tie policy, not a claim of exchange causality. Two replays of the same file produce the same book hash.

Queue inference

Every model joins at the back of displayed size, after subtracting prints at that price the book update has not yet absorbed. Earlier simulated orders at the same price are known and sit in ahead_sim. Unexplained decrease C is displayed size that disappeared and was not a print. Conservative takes C from behind first. Optimistic takes it from ahead first. Probabilistic draws a seeded binomial with probability ahead_public / (ahead_public + behind), exact at or below 4096, normal approximation above. Adds join behind. A depth decrease is not itself a fill.

Fills, cancels, cost

A trade at the limit consumes public ahead, then simulated ahead, then the order. A trade strictly through the limit fills the residual. Aggregate trades are ignored for fills when raw trades exist. A cancel that is effective at or before arrival is rejected and never rests. A fill during an in-flight cancel stands. Spread capture on a buy is mid_at_fill − price. Implementation shortfall on a buy is price − decision_mid. Fees hit the ledger immediately and are not subtracted again in those columns. Markouts use a later mid and are ex-post only.

Sensitivity and disagreement

The session grid varies submit delay and queue model on one synthetic book. The five-event divergence fixture is built so the cancellation rules can disagree. Report both. Do not average the models into a true queue.

dune exec queue_positioning -- experiment \
  --config configs/queue_sensitivity.json
dune exec queue_positioning -- experiment \
  --config configs/divergence.json

05 — Validation and reproducibility

Tests lock the engine. They do not certify a fill on Binance.

dune runtest covers checksums, depth sync, duplicate and gap handling, replay determinism, checkpoint resume, queue-model disagreement on the divergence events, no double-count of a print, cancel/fill races, ledger identities, fee arithmetic, Binance JSON decode, and a QCheck random book update. The property test prints a seed. Frame encode/decode for the capture socket is python3 scripts/capture_binance.py --self-test.

Passing those tests means the stated rules are implemented and deterministic. It does not mean a modeled fill would have been the exchange’s fill. The session’s equal fill rates across models are an allowed result of the generator. They are not allowed to be silently forced apart.

06 — Limitations

These are part of the result, not a footnote.

Market-by-price

Public Binance depth is an absolute quantity at a price. Individual order identity and true queue position are not in the feed and must be inferred.

Synthetic is not live

The committed experiments validate controlled scenarios. They are not evidence of live-market fill probability or of profitable execution.

Replay is not prediction

A matching book hash means the engine applied the file. It does not mean the queue model is the exchange, or that a decision using it would have made money.

No live Binance depth is in the committed dataset. A capture attempt in this build environment failed with HTTP 451 on the first REST call. No raw file was written and no depth was invented. The offline protocol fixture in test/fixtures/protocol_example did normalize to a live book. A capture with network access to Binance is a different run and is not redistributed here.

Latency values in the grid are scenario assumptions, not measured round-trips. The 100 ppm fee is not a Binance fee-tier lookup. Int64 multiplication in the ledger wraps on overflow. The probabilistic normal tail for n > 4096 is not an exact binomial. Block bootstrap does not remove all dependence. Fuller list: docs/assumptions_and_limitations.md.

07 — Repository and usage

Commands from the current CLI.

Build and test

opam install . --deps-only --with-test
dune build
dune runtest
python3 scripts/capture_binance.py --self-test

Fixture, validate, replay

dune exec queue_positioning -- generate-fixture \
  --out data/processed/synthetic/session --steps 4000 --seed 7
dune exec queue_positioning -- validate \
  --dataset data/processed/synthetic/session
dune exec queue_positioning -- replay \
  --dataset data/processed/synthetic/session

Normalize, capture, benchmark

dune exec queue_positioning -- normalize \
  --raw test/fixtures/protocol_example \
  --out /tmp/queue_positioning-protocol --symbol BTCUSDT
dune exec queue_positioning -- capture \
  --symbol BTCUSDT --duration-seconds 30 \
  --out data/raw/btcusdt-30
QUEUE_POSITIONING_PROFILE=release dune exec --profile release \
  queue_positioning -- benchmark \
  --dataset data/processed/synthetic/session \
  --synthetic-events 200000 --out reports/bench.json

Exit codes: 0 success, 1 failed validation or a gap, 2 bad usage. simulate and experiment are the same runner. Do not commit raw captures.
